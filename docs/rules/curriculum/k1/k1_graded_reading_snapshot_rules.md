# K1 Graded Reading Snapshot Rules

**Version:** 1.0  
**Date:** 2026-06-25  
**Status:** Active operational rule for K1 RAZ AA book snapshots

## 1. Purpose

This document defines the standard structure and quality boundary for K1 graded reading book snapshots.

Use this document when:

- extracting a K1 RAZ selected book into a snapshot Markdown file;
- reviewing or revising existing K1 snapshots;
- preparing upstream source material for `Course B: Graded Reading`;
- checking whether a snapshot is detailed enough for curriculum use without drifting into a lesson plan.

A snapshot is:

- a book-based extraction document;
- an upstream curriculum source;
- a bridge between raw reading resources and course-track writing.

A snapshot is **not**:

- a full lesson plan;
- a final teacher page;
- a full reading-course file;
- a detailed assessment design.

## 2. Scope

These rules apply first to K1 RAZ AA selected books, including the current Unit 1 reading set, and can later be extended across the rest of the K1 graded reading line.

## 3. Core Principle

A good snapshot should answer:

1. What is this book mainly about?
2. What kind of visual or setting support does it give?
3. What repeated sentence pattern does it offer?
4. What key vocabulary or function words are worth noticing?
5. Why does it fit this unit?
6. How is it most likely to be used in early shared reading?

It should support curriculum design without over-deciding the final course page.

## 4. Required Snapshot Structure

Every snapshot should use this exact structure:

````markdown
# [Book Title] — Book Snapshot

## Book Identity

- File Code:
- Unit:
- RAZ Level:
- Book Title:
- Author / Illustrator:
- Word Count:
- Resource Set:

## Main Idea

## Main Scene / Setting

## Key Repeated Sentence Pattern

## Key Vocabulary

## Useful Function Words

## Theme Relevance

## Core Reading Use

## Optional Extension Use

## Suggested Placement in Unit
````

Do not add extra top-level headings unless there is a strong operational reason.

## 5. Field-by-Field Rules

### 5.1 Book Identity

Keep this field factual and compact.

Include:

- file code;
- unit;
- level;
- title;
- author / illustrator if available;
- word count if available;
- resource set.

Do not add commentary here.

### 5.2 Main Idea

Explain the book’s core idea in 2–4 sentences.

Good content:

- what the book is mainly doing;
- whether it is a sequence, catalog, portrait book, simple narrative, routine book, or photo essay.

Do not:

- retell every page;
- over-interpret emotionally;
- turn this into teacher guidance.

### 5.3 Main Scene / Setting

Explain the visual or situational frame.

Good content:

- one setting;
- shifting settings;
- portrait sequence;
- home scene;
- bedtime room;
- snack table;
- people-photo sequence.

Do not:

- invent storyline if the book does not have one;
- over-describe illustration style unless it affects teaching use directly.

### 5.4 Key Repeated Sentence Pattern

This is one of the most important fields.

State:

- the main repeated frame;
- a special closing line if relevant.

Examples:

- `My ___.`
- `The ___.`
- `I see ___.`

Keep this field brief and precise.

### 5.5 Key Vocabulary

Only include genuinely central words.

Prefer:

- recurring nouns;
- recurring verbs;
- key theme words;
- words that are likely to matter in shared reading.

Do not:

- dump every possible word from the book;
- mix too many interpretive expansions;
- overbuild vocabulary lists.

Target range:

- about 5–10 items unless there is a strong reason for more.

### 5.6 Useful Function Words

Only include function words that are genuinely useful for pattern awareness or comprehension support.

Examples:

- `my`
- `the`
- `and`
- `for`

Do not force this field to be long.

If the book has only 1–2 useful function words, that is enough.

### 5.7 Theme Relevance

Explain the book’s relevance to the current unit theme.

This field should answer:

- is it directly on-theme?
- is it strongly linked?
- is it a useful bridge?
- does it fit early, middle, or late in the unit?

Do:

- use calm curriculum reasoning;
- explain relation to other selected books in the same unit when useful.

Do not:

- oversell every book as perfect;
- write marketing-style praise;
- over-prescribe the whole unit sequence.

### 5.8 Core Reading Use

This is the practical heart of the snapshot.

Write only the most likely, most defensible reading uses.

Good categories:

- vocabulary focus;
- repeated pattern practice;
- picture walk;
- shared reading;
- sequencing;
- pointing, matching, or acting out;
- comprehension through pictures.

Do:

- stay grounded in the book;
- write what teachers are most likely to use first.

Do not:

- list every possible classroom activity;
- mix in too many extensions;
- drift into complete lesson planning.

Target:

- about 3–5 bullets.

### 5.9 Optional Extension Use

This field must stay light.

Use it for:

- 1–3 reasonable extension ideas;
- optional follow-up directions;
- simple, clearly grounded cross-links if genuinely useful.

Good examples:

- a conversation prompt;
- a simple drawing prompt;
- a simple role play;
- one hands-on follow-up.

Do not include:

- assessment plans;
- closing ceremony ideas;
- cultural commentary unless absolutely necessary;
- too many cross-curricular branches;
- detailed craft procedures.

Target:

- about 2–4 bullets maximum.

### 5.10 Suggested Placement in Unit

Explain why the book fits its current lesson slot.

Good content:

- why it works as L1, L2, L3, or L4;
- what it depends on from earlier books;
- what it prepares for in later books.

Do:

- keep this concise;
- keep this curriculum-focused.

Do not:

- over-script class timing;
- overstate “best taught at...”;
- include ceremony, assessment, or event suggestions unless absolutely core.

Target:

- about 3–5 bullets.

## 6. Style Rules

### 6.1 Tone

Tone should be:

- professional;
- calm;
- teacher-friendly;
- curriculum-facing;
- lightly analytical.

Avoid:

- sales-like praise;
- inflated claims;
- emotionally overblown language.

### 6.2 Prefer Extraction Over Invention

If the book clearly supports a use, say it.

If the book only loosely suggests a use, write it lightly.

Do not invent:

- hidden symbolism;
- unsupported developmental claims;
- heavy teaching strategy not visible from the book;
- curriculum meaning that depends more on imagination than on the resource itself.

### 6.3 Do Not Over-Teach In The Snapshot

A snapshot is not the place to finalize:

- assessment design;
- ceremony ideas;
- detailed cross-curricular planning;
- moral interpretation;
- classroom schedule timing.

Those belong later in:

- `Course B: Graded Reading`;
- lesson framing;
- teacher-facing planning pages.

## 7. Allowed vs Not Allowed

### Allowed

- repeated sentence pattern analysis;
- vocabulary extraction;
- scene / setting explanation;
- unit-fit reasoning;
- likely reading-use reasoning;
- light extension ideas.

### Not Allowed

- detailed lesson plans;
- minute-by-minute teaching steps;
- full assessment design;
- event tie-ins unless essential;
- inflated claims;
- long theory explanations.

## 8. Revision Priorities For Existing Snapshots

When revising existing K1 snapshots:

### Keep

- the current structure;
- repeated pattern observations;
- unit sequence logic;
- most core reading use ideas.

### Reduce

- over-specific assessment suggestions;
- event-specific tie-ins unless essential;
- ceremony-style ideas;
- broad cultural commentary unless strongly needed;
- too many optional extensions.

### Standardize

- similar detail level across books;
- similar bullet density;
- similar tone;
- similar strength of inference.

## 9. Final Quality Check

Before marking a snapshot ready, confirm:

1. Does it describe the book clearly?
2. Does it identify the key repeated pattern?
3. Does it keep vocabulary focused?
4. Does it explain unit relevance without overclaiming?
5. Does `Core Reading Use` stay practical and limited?
6. Does `Optional Extension Use` stay light?
7. Does `Suggested Placement in Unit` explain sequence logic without over-directing teaching?
8. Does the whole document feel like an extraction file rather than a lesson plan?

## 10. Completion Report Requirement

After revising or creating snapshots, report:

- files reviewed;
- files revised or created;
- whether the structure changed;
- whether any fields were removed or merged;
- major normalization decisions;
- whether the snapshots are now ready to serve as `Course B` upstream source.
